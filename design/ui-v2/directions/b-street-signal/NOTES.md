## 1. Thesis

**The phone is the poster for a game that is happening right now.** ManHunt is not a dashboard about a hunt and
it is not a sports broadcast; it is a flyer for tonight's game, the paper code plate the host holds up, the kit
tag on a player's back, the stamped full-time board on the wall afterwards. So the app is composed like
**street print**: one big idea per screen, oversized display words and numerals in Big Shoulders at sizes a real
poster would use, flat colour fields with hard edges (no gradients, shadows, glass or noise textures), and the
physical gestures of printed matter — **tape, stencil bridges, rubber stamps, die-cut kit tags, a marker
annotation, tally marks** — used as the component grammar instead of cards. The loudness is spent on the few
moments that are actually loud — the room code, the clock, the winner, the claim — and it is spent through
**scale and flat colour**, the two poster tools that survive at night and at arm's length. Everything else pulls
back to calm ink, the UI typeface, generous space, and a bottom action dock that never moves.

The one sentence to hold on to: **a poster over the field — loud on the ceremony, quiet on the operation.**
If a screen is read while someone is running in the dark with one thumb, the poster dial drops to nearly zero:
clock, map, one full-width action, and honest status — and nothing decorative touches them.

## 2. The two registers (the rule that protects usability)

This is the central system decision and the answer to this territory's stated risk ("highest; must stay calm and
legible under stress").

| Register | Screens | Loud | Calm |
|---|---|---|---|
| **Poster** (ceremony) | auth, roles, home, lobby, result, history, settings, `lobby-rtl`, `home-light` | one display object per screen (brand line, the two verbs, the code, the winner), one or two big flat colour fields, tape/stamp gestures | all body copy, inputs, rows: 16 sp Instrument Sans on ink at AA contrast |
| **Placard** (operation) | hunt-hunter, hunt-prey, chat, tag claim, room rules | the clock (display numerals), the state word, one coral/violet field where the game's own data lives | the map, the log, the decision copy; no rotation, no stencil on data, no tape over controls |

**Inspection test:** a screen fails if you cannot name its one big object in under one second, if the primary
action is not a full-width block in the bottom **40 %** reach zone, or if any text you must read sits over a
colour field it does not clear 4.5:1 against.

**Loudness budget per screen:** at most **one display moment ≥ 48 sp** and at most **one additional data
moment** (clock/code/score). Max two flat colour fields. If content needs more room, the poster gets *smaller*,
never the body text.

## 3. Composition — the poster grid

### 3.1 Rules

1. **One subject block.** Every screen has one flat block that carries its subject (the verb, the code, the
   clock, the winner). The block bleeds to the top screen edge and to the left/right edges; inner content keeps
   the 24 dp margin. Its bottom edge is a hard horizontal cut — never rounded, never feathered. Everything else
   sits on the ink ground below it.
2. **Poster stacking.** Canonical vertical order: **tape/credit line → subject block → working area → credits
   strip → action dock.** Reads like a flyer: headline, detail, small print, call to action.
3. **Hard cuts, not cards.** No container radius above 2 dp. Grouping is done with flat fields, 1–2 dp rules
   and space. Nothing is nested inside another surface; no drop shadows anywhere (the only "elevation" is a
   sticker or tape overlapping an edge by 4–8 dp).
4. **Asymmetry on a straight spine.** Type is left-aligned to the 24 dp margin (mirrored in RTL); the left rule
   is the poster's spine. Big display objects may be optically centred only when they are one word or a code.
   One deliberately off-grid object per screen is allowed (a tape strip at −1.5°, a stamp at +3°) — never two
   competing ones, never on a control.
5. **Margins are print margins.** 24 dp side margins; 20–24 dp inside blocks; no text crosses the margin.
6. **Edges are visible.** A flat field on the ink ground gets a 1 dp chalk-at-18 % rule on its exposed edge so
   the block edge is perceivable without shadow. Non-text contrast ≥ 3:1 where the edge is a control boundary.
7. **The dock is constant.** Every screen carries one action dock at the bottom: 24 dp side margins, 24 dp
   bottom inset, primary block 60 dp, optional secondary line 44–48 dp above/below. Same place on every page,
   in both registers, so the thumb learns one address.
8. **No card stacks, no list cards.** Lists are ruled rows; settings are ruled sections; the team sheet is two
   flat columns. A "card" appears only when it is a **physical object** in the metaphor: a ticket stub
   (history), a kit tag (player), a stamp (event).

### 3.2 Spacing scale (dp)

`2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64`. Base 4. Side margin 24. Block padding 20/24. Gap between poster
sections 24–32. Row height 56 (two-line 64–72). Tape strip 26 (28 with padding). Stamp padding 10/18.
Dock: 24 side, 16 gap, 24 bottom. Canvas 390 × 844 dp.

### 3.3 The dock (constant across every page)

```
┌─────────────────────────────────────────────┐
│  [ secondary line · optional ]              │  44 dp: outline block / inline action
│  ┌───────────────────────────────────────┐  │
│  │            Primary action             │  │  60 dp flat block, 0 radius
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

- Primary = the screen's one action, sentence case, Instrument Sans Bold 16, ink label on a cyan fill (or a
  chalk fill where cyan is already the subject — see colour rules). Variant used on Home: **two side-by-side
  blocks** for the two verbs (Create hunt primary cyan / Join hunt outlined), both inside the reach zone.
- Secondary = 1.5 dp chalk-at-24 % outline on ink, 52 dp.
- In the Poster register a quieter action may sit above the primary as an inline text action (48 dp hit
  height), never as a second filled block.
- In RTL the dock mirrors (primary still full width; secondary line right-aligned).
- No icon-only primary actions anywhere; destructives are never adjacent to the primary.

## 4. Type

### 4.1 Faces (approved, bundled, OFL)

- **Display / posters / numerals:** Big Shoulders Bold (Regular for rare meta). Condensed signage shapes are the
  poster voice; set tight-leading and large.
- **UI / body / buttons / rows:** Instrument Sans Regular + Bold. The legibility family; all functional text.
- **Machine data:** Red Hat Mono Regular: room code, clock digits, timestamps, zone radius, version, server
  address and system state words. Never prose. Digits tabular everywhere.
- **Arabic:** never Latin display for Arabic. The env ships **IBM Plex Sans Arabic** (OFL) paired with the brand
  stack for the RTL proof; Arabic display may use it at 40–48 sp, no tracking, generous line height. Numerals
  and the room code stay Latin/LTR.

### 4.2 Scale (390 dp reference; line-height sp; tracking em)

| Token | Size/LH | Face | Use |
|---|---:|---|---|
| `poster.xxl` | 96/84, −0.02 | Big Shoulders Bold | The single loudest word ("Hunters win."), max 2 lines. |
| `poster.xl` | 76/68, −0.015 | Big Shoulders Bold | The two Home verbs ("Host", "Join"), claim word, auth brand line at 68. |
| `poster.l` | 60/56, −0.01 | Big Shoulders Bold | Section declarations, result duration. |
| `poster.m` | 44/44, −0.005 | Big Shoulders Bold | Counts, mode names, block titles, team header words. |
| `clock` | 64/64, tnum | Big Shoulders Bold | Live clock. Never below 48. |
| `data.hero` | 58/60, +0.02 | Red Hat Mono Regular | Room code on Lobby (K7M2QX). |
| `title` | 22/26 | Instrument Sans Bold | Screen titles, sheet titles, room name. |
| `body` | 16/24 | Instrument Sans Regular | All copy that must be read (B uses 16 for night legibility). |
| `body.small` | 14/21 | Instrument Sans Regular | Supporting rules/notes. Floor for prose. |
| `label` | 14/18 | Instrument Sans Bold | Buttons, rows, tags. |
| `caption` | 12/17 | Instrument Sans Regular | Auxiliary small print only. |
| `data` | 12/17, +0.06 | Red Hat Mono Regular | Code, time, zone, version, metadata. |
| `state` | 11/15, +0.12, caps | Red Hat Mono Regular | Only `LIVE`, `HEAD START`, `PAUSED`, `FULL TIME`, `CANCELLED`, `LOBBY`. |

**Rules**
1. Display type only for strings ≤ 4 words that are glance information (verb, code, clock, winner, state).
   **Never** display for body, form labels, names in rows, error text or buttons.
2. 13 sp is the floor for any text a player must read; `caption`/`data` at 12 sp are auxiliary only and must
   clear 7:1. No text below 11 sp. Body text ≥ 14 sp per the workstream.
3. **Sentence case everywhere.** No ALL-CAPS headings, eyebrows, buttons or section labels. Uppercase is
   reserved for: true state words (`LIVE`, `FULL TIME`…), true data labels (`ZONE 240 m`, `PREY 2 / 2`, `HOST`,
   `YOU`), and the invite code. Display words are typed in sentence case — Big Shoulders does the shouting, not
   the caps ("Hunters win.", "Tag claim", "Host").
4. Tracking: display −0.015/−0.02 em; mono +0.04/+0.06 em; Arabic 0. No faux-bold, no outlined type.
5. Display scales at half rate with system font scale (cap 1.25×); body/label scale 1:1. No fixed heights on
   text; blocks use padding + `heightIn`. Poster words wrap to 2 lines max or step down a size.
6. Max line length 64 characters for body; 2 lines max for a display line.

### 4.3 Stencil bridges (the signature type treatment)

At display sizes ≥ 56 sp, a **non-data** word may carry one or two stencil bridges: 4–6 dp bars in the block's
background colour crossing the letterforms at ~30 % and ~70 % cap height, as a sprayed stencil would. Drawn as
overlays, never as a new font, and the real text stays underneath for screen readers.

- Allowed: "Hunters win.", "Tag claim", "Host"/"Join", "Riverside Run" (Lobby room name), the brand line.
- **Never**: the clock, the room code, player names, scores, errors, or anything parsed under stress.
- Max 2 bridges per word, max 2 stencilled words per screen. If the word is needed for navigation, no bridge.

## 5. Colour — flat print inks

Semantic roles are fixed and shared with A/C: **cyan = field/referee/time; coral = Prey; violet = Hunters;
ink = ground; chalk = markings/type; error = destructive only.** B reweights the *areas*, not the meanings:
colour appears as large flat blocks, not tinted chrome.

### 5.1 Block roles

| Block | Fill | Text | Where |
|---|---|---|---|
| `field` | ink `#0B1220` | chalk `#E6EDF7` | Default ground everywhere. |
| `ink-lift` | `#101A2C` | chalk | Working blocks that need separation from the ground (ticket stubs, log rows) — 1 dp rule, no shadow. |
| `paper` | chalk `#E6EDF7` | ink `#0B1220` | **Small print objects only**: stickers, ticket stubs, tape, stamps, the code plate on paper. Never a full-page or full-form background (night test — no giant white/glare field). |
| `signal` | cyan `#22D3EE` | ink `#04222B` | The one action or the one live/time surface. One per screen. |
| `prey` | coral `#FF7A59` | ink `#0B1220` | Where the Prey are the subject (team header, Prey-win result, tag-claim header, prey marker). |
| `hunters` | violet `#A79BFF` | ink `#0B1220` | Where the Hunters are the subject (team header, Hunters-win result, hunter marker). |
| `ink-over` | ink | chalk | Inverted action on a light block. |

Small text on colour blocks uses near-black ink for both team colours (7.3:1 coral, 7.8:1 violet) — always paired
with the word `Prey`/`Hunters` and a glyph, never colour alone.

### 5.2 Rules

1. **One filled cyan surface per screen.** Team-colour fields that identify the subject (roles, lobby headers,
   result winner, claim header) are *data surfaces*, not chrome; the one-hot rule applies to chrome and actions.
   The map is exempt because it is the field itself.
2. **Cyan is never a team.** Team headers are team colours; the clock/live/action is cyan (or, where the
   team’s own colour is the subject, the action takes a chalk fill so only one hot field exists).
3. **No gradients, glows, blend modes, noise textures, glass, shadows.** Flat fills only. The only texture is
   the 1 dp rule and the paper's 1 dp border.
4. **Light theme is daylight chalk.** Ground `#F7F9FC`, ink `#0F172A`, paper `#FFFFFF`, hairlines `#D3DCE8`,
   primary cyan `#0C6B84`, coral `#B33A0F`, violet `#5B21B6`, error `#B91C1C`. Ink blocks **stay ink** in light
   theme with chalk text (a scoreboard does not change colour with the weather). Composition identical; only
   the inks change. Proven on `home-light`. No cream/parchment, no pure black.
5. **Error** is a 2 dp error rule + error text + 20 dp glyph on its block, never a filled red card, never coral.
6. **Disabled** = 38 % label opacity, block keeps its edge; never a grey fill.

## 6. Material gestures (diegetic, original vector)

The gestures are how B stays street print without stock imagery. Each has strict rules so it cannot hurt
legibility.

1. **Tape** — a flat strip (paper or team colour) with mono label, rotated **−1.5° to +2°**, one per screen
   typically, ≤ 3 words, **sentence case** (it is a label, not an eyebrow). Non-interactive; never the only copy
   for an action; never overlaps a control or a body line. Tape sticks with a 1 dp ink edge (a rule, not a
   blur). In RTL the rotation mirrors sign.
2. **Stencil** — the bridge treatment in §4.3. Also used structurally: a data label set in tracked mono on a
   1 dp rule; the room code set like a stencilled crate code (mono, tracked, on ink).
3. **Stamp** — a rotated (+2° to +3°) double-rule box with a display word and optional mono sub-line, used
   **only for events**: full time, tag claim, cancelled. Max one per screen; never over body text; always
   accompanied by the same information in plain text elsewhere. 2 dp rules; a second inner rule gives the
   "rubber stamp" authenticity.
4. **Kit tag / sticker** — cut-corner blocks (top-end cut 6–8 dp) for players (solid team fill + ink name),
   mode availability and the settings entry. 28–32 dp tall; ≥ 48 dp hit target when interactive (transparent
   padding).
5. **Marker** — one hand-drawn vector annotation per screen maximum: a wobbly underline under the code, a curved
   arrow on Auth from the brand line to the create-account action, a circled radius on the hunt. Original SVG /
   Compose Path with 2 px stroke and ±1 px wobble; never under body text; always duplicated in text.
   Decorative semantics only.
6. **Tally** — readiness counts may render as tallies (`IIII` + slash) at 2 dp strokes, but the numeral is
   always present too ("5 / 5 ready" + tally). Never the only representation.
7. **Ticket perforation** — a 1 dp dashed rule (6-4 cadence) as the edge of history stubs; the only dashed rule
   in the system besides the map's data dashes (stale marker ring).

**Never:** torn-paper bitmaps, xerox noise, spray drips, halftone gradients, wet-paint effects, sticker peel
highlights, drop shadows under tape, rotation on controls or multi-line text, stickers as decoration only.

## 8. Motion intent (brief; not rendered in the page set)

Motion in B is **poster production**: paste, press, peel — not app animation. Hard cuts, no springs, no
overshoot, no glow. The rules below are intent for the implementation pass; the HTML pages are static.

| Cue | Behaviour | Where |
|---|---|---|
| Screen change | Hard cut with a 1-frame ink inversion, 80 ms; no slide; the dock does not move | all navigation |
| Poster paste | Subject block + tape land as a unit: 120 ms, cubic-out, 2 dp settle offset (no bounce) | first composition |
| Stamp press | Winner/claim stamp scales 1.06 → 1.0 in 120 ms and holds; one inverted frame | result, tag claim |
| Sticker slap | Kit tags appear with a 60 ms stagger *only when a player joins*, never on first render | lobby |
| Tape stick | Tape rotates 0.5° → final angle in 80 ms | once per screen max |
| Clock tick | digits change without easing; a 1 px tally tick advances under the strip | hunt strip |
| Zone/trail/ping | linear draws 400–600 ms (shared brand motion) | map |
| Tag snap | violet ring closes on the coral dot in 120 ms, hard cut, invert frame | map, hunt |
| Full time | the frame cuts to the result poster; no crossfade | result |
| Reduced motion | every cue = final static frame; no loop; the poster still carries the information | all |

**Never:** fade-and-slide entrances for every element, parallax, particles, glow pulses, shimmer-loading,
springs. The dock and the clock never animate on entry — they are instruments, not content.

## 9. RTL / Arabic rules (direction-specific)

- The poster composition mirrors: subject block content right-aligned, dock mirrored, team columns swap order,
  tape/stamp/marker rotation sign flips, ticket perforation at the logical end. Never mirror the wordmark/mark,
  the map, numerals or the room code.
- Arabic labels: use the existing MSA strings from `i18n/Localization.kt` wherever they exist. Arabic display
  uses the Arabic face (env ships IBM Plex Sans Arabic; implementation may bundle it — cost below) at 40–48 sp
  with +2 sp leading, **no tracking**, never the Latin display face.
- The room code, clock, timer, count and version are Latin/numeric and pinned LTR inside their own node
  (`dir="ltr"` / Compose `LocalLayoutDirection.Ltr`). No `·` separator in Arabic strings; use a full stop or a
  line.
- Arabic player names are the real test: team rows grow (`heightIn`, wrap to 2 lines, never shrink below label).
  Long names never push the ready tick off-screen; buttons wrap and grow, never clip.
- Any string I write that is not already in `Localization.kt` is marked **`[NEW COPY — needs Arabic review]`**
  in step 2's NOTES diff (see §15). No machine translation is shipped in a page.

## 12. What I deliberately reject (and why)

1. **Gradients, glows, glass, blurred shadows, noise overlays, torn-paper bitmaps.** Brand rule: flat fills;
   also the fastest way for "street poster" to become a costume. No exceptions on any page.
2. **Xerox/registration-misalignment overlays on text.** A poster reference, but it destroys small-type
   legibility at night; kept only as the *idea* of offset — a stamp or tape may be 1–2 px off its rule, text
   never.
3. **Display type in body roles.** The single biggest risk of this territory; banned outright (body 16/24
   Instrument Sans, floor 13 sp).
4. **Stencil cuts on data** (clock, code, names, scores) — data must be parsed at a glance; bridges are for
   non-data display words only.
5. **Rotation on controls, multi-line text, or anything a thumb must hit.** Tape/stamp only, decorative.
6. **ALL-CAPS headings, eyebrows, buttons or section labels.** Sentence case; caps reserved for true state
   words, data labels and the code. (Big Shoulders supplies the poster voice, not caps.)
7. **Large white/paper fields in dark theme.** Night test: no giant chalk block, no lightbox form. Paper is for
   small print objects (stickers, stubs, tape, stamps) — this was a deliberate revision after the playbook's
   night constraints.
8. **Card stacks.** No 16/20/28 dp cards, no icon tiles, no nested surfaces — blocks/rules/tags/rows only.
9. **Pill buttons and floating action buttons.** Flat blocks only (circular 48 dp icon buttons only for
   platform-conventional back/close/map controls, never for navigation).
10. **Fake poster graphics:** no invented gig-poster art, no halftone portraits, no mascot, no stock icons, no
    AI imagery, no external images of any kind. No invented street names or fake OSM tiles: the map is a drawn
    schematic stand-in, labelled honestly.
11. **Sports-app grammar / fake claims:** no broadcast lower-thirds, no "VS" chips, no league tables, no
    "SEASON 01", no fake player counts, ratings or urgency. No rematch implied as shipped (flagged proposal
    only). No store badges or install claims.
12. **Gamer-neon:** no cyan glow outlines, no RGB accents, no scanlines, no HUD reticles.
13. **A second cyan surface, team colour as a warning, coral for errors, three hot colours competing.**
14. **Losing the map to chrome:** hunt pages keep the map full-bleed; the poster dial is off there.

## 13. Risks and controls (this territory's own risk register)

| Risk | Control |
|---|---|
| **Legibility at night / arm's length** | Display only for ≤ 4-word glanceables; body 16/24; all contrast pairs pre-checked; no large paper/white fields on dark pages; no text over busy colour; stencil/tape never on data; the clock and code are the only data at poster scale; dark is primary, light is a translation. |
| **One-handed use** | One dock at the bottom of every page, never moves; primary 60 dp full width (Home = two half-width blocks inside the reach zone); all taps ≥ 48 dp; no critical action in the top third; top-end controls secondary only. |
| **Stress states** (running, GPS, claim, offline) | Two-register rule: hunt/claim/log drop to Placard — no rotation/stencil decoration on controls, one action, calm ink, honest strips; consequence copy before actions; pending claim strip persists until answered; no red flashes. |

| **Density / scroll** | Poster pages are composed to one 390 × 844 viewport where the app's real content allows; scroll regions only where the app really scrolls (roles, settings, chat log, rules sheet) and they scroll inside the page. |

## 14. Compose / feasibility notes (what implementation must know)

- **No engine work required.** All screens map to existing composables/ViewModels: same navigation, same
  actions, same data contract (`RoomScreen`, `MatchMap`, `ChatPanel`, `SettingsScreen`, `MatchSheet`,
  `RoomSettingsDialog`, `ScorePage`, `HistoryDialog`). B changes hierarchy/chrome, not flow.
- **Fonts:** the three Latin faces are already bundled (`android/app/src/main/res/font/`, see
  `ui/theme/BoardTokens.kt`). Arabic: system Arabic fallback is today's honest baseline; the env now ships
  **IBM Plex Sans Arabic** for the proof, and bundling it in the app is the recommended implementation step
  (+~460 KB for two weights — a decision for the implementation pass because the APK target is ~2 MB). The
  proof page states which face it uses; no fake Arabic.
- **Blocks:** `Box`/`Surface` with `color`, zero elevation, `RectangleShape` or 2 dp `RoundedCornerShape`.
  Paper/signal/team fills are token roles; no gradients/brushes → no new graphics stack.
- **Tape / stamp:** `Modifier.graphicsLayer { rotationZ = -1.5f }` on a static `Box`; rotation does not affect
  layout; keep the interactive target outside the rotated layer. Semantics: tape decorative
  (`clearAndSetSemantics {}`) with the information duplicated in plain text.
- **Stencil bridges:** draw 2 `Box`es (or `drawWithContent` + `drawRect`) over the display `Text` using the
  block background colour; text remains real text for a11y. No `BlendMode`, no shader, no custom font.
- **Marker annotation:** one original `ImageVector`/`Canvas` path per screen (wobble baked into the path);
  decorative only; vector drawable like the existing `FieldMarks.kt`.
- **Kit tags:** `CutCornerShape(topEnd = 8.dp)` already exists (`BoardShape.tag`); solid fill + ink label;
  48 dp hit wrapper when interactive.
- **Ticket perforation:** `PathEffect.dashPathEffect` on a 1 dp `Canvas` rule — no bitmap.

## 16c. Three stealable ideas for the other directions

1. **The room code as a stencilled crate code** (poster-scale mono code + marker underline + "Tap to copy").
   Any direction can make the invite code the social object at ~58 sp - it is the single most legible thing at
   thumbnail scale, and it costs nothing but type scale.
2. **Ticket-stub history with a dashed perforation** (1 dp dashed edge + result word in the winner's colour +
   duration in mono). A physical record beats a card list; the perforation is flat, cheap, and works in light
   and dark without any texture.
3. **The two-register rule** (poster loudness on ceremony screens, poster dial to near-zero on operation
   screens), expressed as an explicit loudness budget. Even if a direction does not use tape/stamps, copying
   the budget (max one display moment + max two colour fields + one dock) is a cheap way to keep a loud
   direction usable under stress.
